# Research: audio (16/11/2026, Haiku 5.5 agent, read-only; verify items marked UNVERIFIED)

**Research report: procedural engine audio on iOS 18+ (Swift 6, SwiftUI/RealityKit, GitHub macos-26 CI)**

Verification caveat: several Apple pages returned only their titles (AVAudioSourceNodeRenderBlock, AVAudioSession.ambient, interruptionNotification, enableManualRenderingMode), so exact signatures and wording from those pages are UNVERIFIED. Items marked UNVERIFIED are from general knowledge and need checking against the live SDK headers before you rely on them.

## Findings

**1. AVAudioSourceNode render block**
- Init: `AVAudioSourceNode(format:renderBlock:)` (and `init(renderBlock:)`). Source: https://developer.apple.com/documentation/avfaudio/avaudiosourcenode/init(format:renderblock:)
- Apple (WWDC19 session 510): "When rendering to an audio device, the block operates under real-time constraints, which means that within the block there shouldn't be any blocking calls like memory allocations, call to lib dispatch, or blocking on a mutex." The session says nothing about these constraints in manual mode. Treat them as applying in both modes. Source: https://developer.apple.com/videos/play/wwdc2019/510/
- Same session: the node works in real-time and manual rendering modes, has one output and no input, and supports linear PCM sample-rate and bit-depth conversion. Source: https://developer.apple.com/videos/play/wwdc2019/510/
- Apple's sample "Building a signal generator" uses this node with a custom render callback. Source: https://developer.apple.com/documentation/avfoundation/audio_track_engineering/building_a_signal_generator
- Block signature (from memory, UNVERIFIED): `(UnsafeMutablePointer<ObjCBool> isSilence, UnsafePointer<AudioTimeStamp>, AVAudioFrameCount, UnsafeMutablePointer<AudioBufferList>) -> OSStatus`.
- Swift 6 Sendable: I could not confirm whether the render block parameter is `@Sendable` in the iOS 18/Xcode 26 SDK (UNVERIFIED). Expect strict-concurrency warnings. The fix is to capture only a final class holding lock-free state (Synchronization `Atomic` or a preallocated SPSC buffer, UNVERIFIED availability on iOS 18), never `self` from a `@MainActor` view model.
- Real-time safety in Swift: Swift Forums consensus is cautious. Avoid Swift arrays that grow, String, print, actors, dispatch, locks, and ARC churn in the render path. Source: https://forums.swift.org/t/realtime-threads-with-swift/40562
- RealtimeSanitizer (`-fsanitize=realtime`, `[[clang::nonblocking]]`) targets C/C++. Its applicability to Swift is UNVERIFIED. Source: https://clang.llvm.org/docs/RealtimeSanitizer.html

**2. Sample rate and latency**
- Request 48 kHz with `AVAudioSession.setPreferredSampleRate(_:)` and a small buffer with `setPreferredIOBufferDuration(_:)`. These are preferences, not guarantees. Read back `sampleRate`, `ioBufferDuration`, `outputLatency` after `setActive(true)`. Forum reports show rate changes on Bluetooth routes and an iOS 18 case where the requested buffer was ignored when Sound Recognition or Vocal Shortcuts was enabled. Sources: https://developer.apple.com/forums/thread/769245 and https://developer.apple.com/library/content/documentation/Audio/Conceptual/AudioSessionProgrammingGuide/OptimizingForDeviceHardware/OptimizingForDeviceHardware.html
- The iPhone 13 native rate of 48 kHz is UNVERIFIED as a documented fact. Build the source node format from the session's actual `sampleRate` rather than hard-coding it.

**3. Firing-order synthesis**
- For a 4-stroke engine, the firing frequency is `rpm/60 × cylinders/2`. For example, 6000 rpm on a V8 gives 400 Hz. This is standard engine physics (UNVERIFIED citation, derivable from first principles).
- Pulse trains (recommended): each cylinder fires at its crank angle. Keep a crank-angle accumulator in `Double` on the render thread, and emit a decaying exhaust pulse (filtered impulse or damped sinusoid) per cylinder when its angle wraps. Per-cylinder offsets come from the firing-order table.
- Additive: harmonics of the firing frequency with per-harmonic weights. Cheap and deterministic, but less convincing at low rpm.
- Granular: grains from recorded loops. Good texture, but weak control of firing order and hard to test deterministically.

**4. Acoustic differences**
- Cross-plane V8: crank throws 90° apart, so firing order is uneven across banks. Two cylinders on the same bank can fire back-to-back, giving a deeper, burbly note. Heavier crank. Source: https://jalopnik.com/1878133/why-flat-plane-crank-v8-engines-sound-different/
- Flat-plane V8: throws 180° apart, so it strictly alternates banks ("left, right, left, right"). Lighter crank, higher rev range, higher pitched and more even. Source: same. Exhaust-manifold pulse merging is discussed in Carthrottle sources but not verified in primary text.
- Odd-fire V-twin (45° Harley-style): intervals of 315° and 405° of crank rotation, from a single crankpin. Source: https://www.revzilla.com/common-tread/wtatwta-what-is-wasted-spark-ignition-and-do-i-want-it. Uneven pulses produce the characteristic burble. Source: https://issues.cycleworld.com/article/2008/3/1/service
- Specific cylinder firing orders (for example 1-8-4-3-6-5-7-2) are UNVERIFIED here.

**5. AVAudioSession silent switch and category**
- Apple's category table (archived): Ambient is silenced by the Ring/Silent switch and by screen lock, and does not interrupt other apps' audio. Playback is not silenced by the switch, interrupts others' audio by default, and needs the `audio` UIBackgroundModes key to keep playing with the screen locked. Source: https://developer.apple.com/library/archive/documentation/Audio/Conceptual/AudioSessionProgrammingGuide/AudioSessionCategoriesandModes/AudioSessionCategoriesandModes.html
- For an engine-sound feature where sound should play with the switch on, use `.playback` (`AVAudioSession.Category.playback`). For a respectful default, use `.ambient`. This is a product decision.

**6. Interruption handling**
- Observe `AVAudioSession.interruptionNotification`. On `.began`, pause the engine (the session is already inactive). On `.ended`, check `AVAudioSessionInterruptionOptionKey` for `.shouldResume`, then `setActive(true)` and restart. Source for the key names (page body not fetched, UNVERIFIED body): https://developer.apple.com/documentation/avfaudio/avaudiosession/interruptionnotification
- Also observe the engine configuration-change notification (`.AVAudioEngineConfigurationChange`, UNVERIFIED name) and route changes, and rebuild connections when they fire.

**7. Offline rendering to WAV (manual rendering mode)**
- Confirmed from Apple's guide: the engine's input and output are disconnected from hardware; call `enableManualRenderingMode(.offline, format:, maximumFrameCount:)` before `start()`, then loop `renderOffline(_:to:)` and check the returned status (`.success`, `.insufficientDataFromInputNode`, `.cannotDoInCurrentContext`, `.error`). Apple's sample writes with `AVAudioFile(forWriting:settings:)`. Source: https://developer.apple.com/documentation/avfoundation/audio_playback_recording_and_processing/avaudioengine/performing_offline_audio_processing
- Forum risks: `AVAudioPlayerNode` returned silence at the start in offline mode (https://developer.apple.com/forums/thread/111249), and a 4-channel file rendered silent (https://developer.apple.com/forums/thread/119094). Prefer an `AVAudioSourceNode` in offline mode, which avoids the player-node path.
- Runner: GitHub's macos-26 image is reported GA (third-party mirror, https://depot.dev/blog/now-available-macos-26-github-actions). The runner-images README on GitHub was not fetched, so the exact Xcode 26.x list is UNVERIFIED. Whether manual rendering runs headless on a GitHub macOS runner with no audio device is UNVERIFIED. Test it with a smoke job.
- Linux: AVFoundation does not exist on Linux, so no AVAudioEngine there. Swift Testing and `swift test` run on Linux with Swift 6. Source: https://www.swift.org/blog/announcing-swift-6/

## Recommended approach

1. **Pure-Swift core package** (`EngineSynthCore`, no AVFoundation import, no Foundation audio). Contains: firing-order tables, crank-angle scheduler, per-cylinder pulse generator, harmonic/additive option, a seeded PRNG (no `SystemRandomNumberGenerator`), a DSP parameter struct, and a pure-Swift WAV writer (RIFF header plus 16-bit PCM, so no AVAudioFile). Test on Linux with `swift test` using Swift Testing.
2. **Thin adapter target** (`EngineSoundAudio`, Apple-only, guarded by `#if canImport(AVFoundation)`): owns the `AVAudioEngine`, the `AVAudioSourceNode` whose block calls into the core's preallocated `render(into:frames:)`, and session/interruption handling. Parameters pass through a lock-free snapshot (rpm, throttle, load), not by reading main-actor state.
3. **Render path rules**: preallocate all buffers at init, no allocation or growth, copy values not references, and move formatting and logging off the thread.
4. **Tests**: Linux core tests check pulse timing against the firing-order table, Goertzel or DFT peak at `rpm/60 × cylinders/2`, cross-plane vs flat-plane spectral differences, no NaN, peak below 1.0, and WAV round-trip. Use tolerances because libm differs between Apple and Linux. On macos-26, a separate job renders offline via manual mode and checks the output matches the core's output.
5. **Session**: `.playback` or `.ambient` is a product decision. Request 48 kHz and a small buffer, read back the actual values, handle interruptions, and restart on configuration change.

## Risks

- Swift 6 `Sendable` on the render block could force compromises (UNVERIFIED).
- Swift runtime and ARC on the render thread can cause glitches; measure with Instruments (no Mac locally, so this needs a CI or device step).
- Bluetooth and iOS 18 route changes can alter sample rate and buffer size.
- Manual rendering on a headless CI runner is UNVERIFIED; the offline-test job could fail for environmental reasons.
- Cross-platform floating-point differences can make golden-file tests flaky.
- No device or simulator can be run from this environment; all audio verification happens on CI or a real iPhone 13 (not done here).
