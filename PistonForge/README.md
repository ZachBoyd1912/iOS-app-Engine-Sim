# Piston Forge

Build an engine from bare parts, fit it into a car, map the ECU, then prove it on the dyno and
the drag strip. A single-player, offline workshop game. The game is a web app (three.js +
TypeScript + Vite) wrapped for iOS with Capacitor.

## Commands

```bash
pnpm install
pnpm dev          # play in a browser (the address is printed)
pnpm typecheck    # must be zero errors
pnpm test         # unit tests: simulation, save file, phone layer
pnpm smoke        # headless play-through of the real loop + screenshots in shots/
```

Do not run a production build on the development machine (8 GB RAM). CI builds it:
`pnpm build:web` runs in `.github/workflows/ci.yml`, and the iOS project is compiled on a
macOS runner by `.github/workflows/ios.yml`.

## Layout

| Path | What it is |
| --- | --- |
| `src/sim/` | The simulation: engine maths, ECU, dyno, drag, handling, career, save file. Pure TypeScript, no DOM, unit tested. |
| `src/app.ts` | Application actions and the fixed-step loop that drives dyno pulls and runs. |
| `src/game/` | three.js scenes: workshop, dyno cell, strip, procedural car and engine models. |
| `src/ui/` | HTML/CSS console around the 3D stage. |
| `src/audio/sound.ts` | Synthesised engine sound and interface cues (no recordings). |
| `src/platform/` | Everything phone-specific: haptics, background/resume, durable save. The only code that talks to Capacitor is `src/platform/index.ts`. |
| `src/engine/loop.ts` | Fixed 60 Hz simulation loop with interpolated rendering. |
| `ios/` | The Xcode project generated by Capacitor. Committed so CI can build it. |
| `capacitor.config.ts` | App ID, name and web-view settings. |
| `scripts/smoke.mjs` | End-to-end test. |

## Rules for changes

- The simulation stays pure. Numbers live in `src/sim/` with tests; scenes and UI read from it.
- Gameplay state changes only in the fixed step (`App.step`), never in render code.
- Phone features go through `src/platform/`. Game code asks for a cue (`haptics.cue('shift')`);
  it never imports a Capacitor plugin directly. That keeps the browser build and the tests working.
- The save file is versioned. A format change means bumping `SAVE_VERSION` and adding a
  `MIGRATIONS` step with a test in `tests/save.test.ts`. Never reset players' saves.
- Nothing is downloaded after install: no remote code, no remote assets.
- After any change: `pnpm typecheck`, `pnpm test`, `pnpm smoke`, and look at the screenshots.

## Save file

One JSON document in `localStorage` under `pistonforge.save.v1`, with a backup copy of the last
save that loaded cleanly (`.bak`). Inside the iOS app every write is also mirrored to native
storage, and restored from there if the web view's storage is cleared.
